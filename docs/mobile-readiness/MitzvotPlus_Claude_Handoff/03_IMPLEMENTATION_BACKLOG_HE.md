# מצוות+ | משימות ביצוע לקלוד

גרסה 1.0 | 23.11.2026 | תוכנית מוצעת לביצוע, ללא טענה שהקוד נבדק או שהמשימות הושלמו.

## אופן העבודה

יש להתחיל ב-M01 ולהתקדם לפי התלויות. מספר המשימה אינו הוראה לבצע הכול בטור: אפשר לקדם משימות עצמאיות במקביל. הגדרות המימוש נמצאות ב-02_REVISED_TECHNICAL_SPEC.md, והחלטות הבעלים ב-06_DECISIONS_HE.md. משימה שמושפעת מהחלטה פתוחה תסומן בהתאם; ממשיכים בעבודה שאינה תלויה בה, בלי להמציא אישור ובלי לפרסם מוצר בהגדרה שלא אושרה.

P0 הוא פער שחוסם את שער המוכנות הרלוונטי. P1 הוא עבודה שנדרשת לפני הפצת הפיצ'ר או הגרסה שאליהם היא מתייחסת. תכונה אופציונלית אינה פטורה מבדיקה אם היא נכללת בגרסה. אם היא נדחתה, יש לתעד את החלטת ההיקף ולהסיר מהתוצר התנהגות, הרשאות והבטחות שאינן מופצות.

לכל משימה יש לתעד: commit או מזהה תוצר, סביבה וגרסאות, פקודה או תרחיש, תוצאה, ראיה וקושי שנותר. משתמשים ב-DONE, FAILED, BLOCKED או NOT_RUN. קוד שנכתב ללא הרצה אינו DONE כאשר תנאי הקבלה דורש הרצה. אין להכניס סיסמאות, טוקנים או מידע אמיתי של משתמשים לדוח הראיות.

## G0: בסיס קוד והחלטות

- **תנאי קבלה:** דוח מבוסס קבצים מבחין בין React DOM/Vite לבין Expo/React Native או בסיס אחר; ההתקנה, הבנייה והבדיקות הקיימות הורצו במידת האפשר ותוצאת כל פעולה גלויה. טענות 15 המסכים ו-38 הבדיקות אומתו או תוקנו. שינויים קיימים נשמרו.
- **ראיה:** דוח baseline עם SHA, גרסאות, פלט מסכם וגורם לחסימה אם אין גישה. בהיעדר קוד אין להמציא תוצאות או להתחיל הסבה המבוססת על צילום מסך.

### M06 | התחברות וקישורים במכשיר

## G3: ענן, זהות ופרטיות

### M11 | סכמת שרת והרשאות בגישת ברירת מחדל סגורה

- **עדיפות:** P0. **ממצאים:** F07, F11. **תלויות:** M06, M09.
- **ביצוע:** להפריד פרופילים פרטיים וחברתיים, אירועים, ledger, projections ורישומי מכשיר. להגדיר RLS, grants, views ו-RPC, לרבות פונקציות בעלות הרשאות מוגברות.
- **תנאי קבלה:** בדיקות חיוביות ושליליות משתמשות ב-API ובתפקידי משתמש אמיתיים, ולא רק בתפקיד מנהל. משתמש זר אינו קורא או משנה פעילות או עמודות פרטיות; לקוח אינו כותב ניקוד, בעלות או סטטוס שרת. אין service-role בלקוח.
- **ראיה:** migrations, מטריצת הרשאות, בדיקות DB/API ודוח סודות. הרשאות קהילה נבדקות שוב ב-M17.

### M12 | קליטת אירועים, ניקוד ותיקון אטומיים

- **עדיפות:** P0. **ממצאים:** F07, F08. **תלויות:** M09, M11.
- **ביצוע:** לממש validation, canonical payload, uniqueness, כללי ניקוד בגרסה, ledger ותיקון באמצעות void. לבדוק generation שהונפק בשרת ולהפריד תוצאה סופית מ-deferred.
- **תנאי קבלה:** retry של אותו payload אינו מכפיל ניקוד; payload שונה באותו ID נדחה; deferred נבחן מחדש אחרי מועדו. שתי בקשות מקבילות אינן עוקפות מכסה. שני void שונים לאותו אירוע מפצים פעם אחת בלבד. void שמגיע לפני המקור מטופל כתלות ולא מייצר ניקוד שלילי מומצא.
- **ראיה:** בדיקות transaction/concurrency, אובדן תשובה אחרי commit, fixture ניקוד היסטורי וקודי תוצאה מוגדרים.

### M13 | סנכרון דו-כיווני וקבלת שינויים ללא דילוג

- **עדיפות:** P0. **ממצאים:** F08, F13. **תלויות:** M05, M12.
- **ביצוע:** outbox אטומי, receipts, retry, משיכה עם cursor בטוח ביחס ל-commit, pagination, tombstones ו-resnapshot. לשמור cursors לפי חשבון ולנהל pending/accepted/rejected/deferred בממשק.
- **תנאי קבלה:** שני מכשירים מתכנסים לאותו מצב; קריסה בין commit לתשובה אינה מאבדת או משכפלת פעולה; transaction בעל מזהה מוקדם שמתחייב מאוחר אינו נעלם ממשיכה. cursor שפג מטופל בלי החייאת מחיקות. אין הסתמכות על sequence פשוט או updated_at לבדם כהוכחת סדר commit.
- **ראיה:** בדיקות תזמון מקביל, דוח 24 שעות offline, ניתוקים, מחיקת נתון ופג תוקף cursor. סדר הפעולות וה-watermark מתועדים.

### M14 | מיזוג אורח וייבוא מאתר קודם

- **עדיפות:** P0. **ממצאים:** F08, F13. **תלויות:** M06, M13.
- **ביצוע:** לממש migration ID מתמשך, מזהי מקור יציבים, בחירת חשבון יעד וכללי התנגשות. נתונים מאתר קודם מועברים דרך export/import או מסלול מאומת שנבחר; אין הנחת גישה לאחסון הדפדפן.
- **תנאי קבלה:** import שנקטע או חוזר אינו מכפיל ניקוד; אין ערבוב בין שני חשבונות; context היסטורי נשמר כטענת משתמש. קבלת generation של חשבון יעד מתרחשת כחלק מהמעבר המפורש. משתמש מבין מה יישמר, יתמזג או יידחה.
- **ראיה:** תרחישי אורח ריק/מלא, חשבון עם היסטוריה, ניסיון חוזר, יציאה במהלך import וחלופה לנתונים שאי אפשר לקרוא.

### M15 | מחיקת חשבון מקצה לקצה

- **עדיפות:** P0. **ממצאים:** F09, F11. **תלויות:** M06, M11, M13.
- **ביצוע:** תהליך מחיקה ניתן לחידוש באפליקציה ובאתר, אימות זהות, חסימת כתיבות, ניקוי מידע וטוקנים, טיפול בספקים וביטול הרשאות Apple כשיש. להגדיר גיבויים, ראיות מינימליות ומשך שימור.
- **תנאי קבלה:** מכשיר offline ישן אינו משחזר אירועים אחרי מחיקה; session ישן אינו עוקף מצב מחיקה; כניסה חדשה אינה מחייה outbox קודם. כשל ספק חיצוני נרשם ומטופל ואינו דוחה מחיקה ללא גבול. אין הבטחת ניקוי מיידי של מכשיר מנותק או גיבוי אם אינה מתקיימת.
- **ראיה:** תרחישי שני מכשירים, web/in-app, provider failure, גיבוי ושחזור מודע למחיקות. מסמך שימור מאושר לפני השקה.

### M16 | מפת מידע והתנהגות SDK בפועל

- **עדיפות:** P0 לפני איסוף נתונים אמיתי. **ממצאים:** F11, F12, F15. **תלויות:** M02, M11, M15.

- **ראיה:** data map, network trace מסונן, דוגמאות לוגים סינתטיות והחלטות בעלים/משפטיות הרלוונטיות.

## G4: קהילה מצומצמת, אם נבחרה להפצה

### M17 | חברים, הסכמה, ניקוד משותף וחסימה

- **עדיפות:** P0 אם קהילה בהיקף. **ממצאים:** F07, F14, F15. **תלויות:** M02, M11, M12, M13, M15, M16.
- **ביצוע:** הזמנה, קבלה, ביטול קשר וחסימה כ-state machine. להפעיל שיתוף רק בהסכמה ועל allowlist של קטגוריות; להפריד totals פרטיים ומשותפים. לא להעלות ספר כתובות כברירת מחדל.
- **תנאי קבלה:** צד חסום אינו מקבל הרשאת שרת עתידית, אינו שולח אינטראקציה ואינו מקבל הודעה שעדיין בשליטת היישום. cache מטופל בחיבור/תפוגה, בלי הבטחה למחיקת עותק שכבר נמסר למכשיר מנותק. אירועי דיבור וצדקה פרטיים אינם משפיעים על הניקוד המשותף. ההפצה חסומה עד M18.
- **ראיה:** תרחישי חבר, ממתין, זר, חסום, הסרת הסכמה ומחיקת חבר; בדיקות API ו-cache.

### M18 | טיפול בדיווחים וניהול קהילה

- **עדיפות:** P0 אם קהילה בהיקף. **ממצאים:** F14, F15. **תלויות:** M02, M17.
- **ביצוע:** תור moderation והרשאות צוות, דיווח, חסימה, הסרה/הגבלה, פרטי קשר ומדיניות. לבדוק כינויים ושאר שדות שנראים למשתמשים אחרים. למנות אחראי תפעולי.
- **תנאי קבלה:** דיווח סינתטי עובר מקצה לקצה עד החלטה שניתנת לביצוע; המדווח אינו קורא תיקי טיפול של אחרים; לאיש צוות יש הרשאות מצומצמות ותיעוד פעולות. דרישות גיל וסיווג Social נבדקו בהתאם למוצר שנבחר.
- **ראיה:** תרגיל טיפול, מטריצת תפקידים, מסמך אחריות ודרכי פנייה. כפתור דיווח ללא מפעיל אינו סגירת המשימה.

## G5: תוכן והתראות להפצה

### M19 | מהדורות תוכן ותהליך עדכון בטוח

- **עדיפות:** P0 עבור תוכן מופץ. **ממצאים:** F04, F16. **תלויות:** M03, M08, M09.
- **ביצוע:** לאשר מאגר תוכן קטן, רישיון ומהדורה לכל פריט, attribution ו-fixtures; ליישם עדכון נתונים מוגבל בסכמה, integrity, atomic activation ו-rollback. לקבוע מי בודק תוכן ותיקונים.
- **תנאי קבלה:** כל פריט מופץ ניתן לקישור למקור ולזכות שימוש; מהדורה לא מאושרת אינה משלימה חוסרים. attribution זמין offline. הורדה חלקית/פגומה אינה מחליפה תוכן תקין. אין הרצת JS/HTML חופשי או שינוי התנהגות דרך עדכון תוכן.
- **ראיה:** content_license_manifest, אישורי תוכן, בדיקת bundle offline ותרגיל כשל/rollback.

### M20 | מדיניות התראות, שבת ופרטיות מסך נעילה

- **עדיפות:** P0 אם התראות בהיקף. **ממצאים:** F05, F06, F11. **תלויות:** M02, M07, M09, M16; גם M17-M18 עבור push חברתי.
- **ביצוע:** ליישם eligibility בעת תכנון ושליחה, TTL/expiry, deduplication, ביטול תזמונים והחלפת טוקן. להשתמש בטקסט ניטרלי ולתזמן מופעים חד-פעמיים בטווח מוגבל. להפריד שליחה, קבלת ספק והצגה בפועל.
- **תנאי קבלה:** רשת שמתנתקת לפני שבת וחוזרת בשבת, Doze, תהליך סגור, החלפת עיר/שעון, logout, deletion וסירוב הרשאה נבדקו לפי יכולות הנתיב. תוצאה חסומה/לא ניתנת לשליטה אינה מתוארת כהצלחה מובטחת. נוסח המוצר אושר בהתאם למגבלות; ערוץ שאינו עומד בדרישה שנבחרה נשאר כבוי.
- **ראיה:** מטריצת מסירה לפי פלטפורמה ומצב, timestamps מנוטרלים ממידע אישי, הרשאות merged בפועל ונוסח הבטחת המוצר.

### M22 | ביקורת תוצר בינארי ודרישות SDK
