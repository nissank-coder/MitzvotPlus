# Supabase: מצב קיים והמשך ההקמה

**עודכן בסבב 13 (26.11.2026).** הפרויקט `mitzvotplus-staging` כבר קיים, באזור Frankfurt. אין צורך לפתוח חשבון או פרויקט חדשים, ואין למחוק בו דבר.

> **לא לייצור.**
> - סנכרון בגרסת הייצור נשאר כבוי.
> - אין לפתוח פרויקט ייצור לפני שאישרת מדיניות פרטיות ולפני שעברו בדיקות הקבלה ב-staging.

## 1. לבדוק את המצב לפני כל שינוי

אסור להניח שהפרויקט ריק. לפני שמחילים מיגרציה, בודקים מה כבר יש בו. יש שתי דרכים, ואף אחת מהן לא משנה דבר.

**א. בדיקה אוטומטית לקריאה בלבד** (`scripts/staging/probe.mjs`):
- **מה היא צריכה:** רק את הכתובת ואת המפתח הציבורי. לא סיסמה ולא מפתח סודי.
- **מה היא בודקת:**
  - אילו ספקי התחברות פעילים;
  - האם הפונקציות של כל מיגרציה קיימות;
  - שמשתמש אנונימי לא יכול להפעיל אותן ולא רואה שורות בטבלאות.
- **איך מריצים:**
  ```bash
  STAGING_SUPABASE_URL=https://<ref>.supabase.co STAGING_PUBLISHABLE_KEY=sb_publishable_... node scripts/staging/probe.mjs
  ```
- **בדיקה עצמית מול התחליף המקומי:**
  ```bash
  node scripts/staging/probe.mjs --local
  ```

**ב. בלוח הבקרה:** Database → Migrations. שם רואים אילו מיגרציות הוחלו. עם CLI:
```bash
supabase link --project-ref <ref>
```
```bash
supabase migration list --linked
```

## 3. המפתח הציבורי

- פרויקט חדש ב-Supabase נותן **publishable key** (`sb_publishable_…`). פרויקטים ישנים קוראים לו anon key.
- **מה האפליקציה מקבלת:** אחד משני השמות:
  - `VITE_SUPABASE_PUBLISHABLE_KEY` (מועדף);
  - `VITE_SUPABASE_ANON_KEY`.
- **ה-CSP:** מותרת רק כתובת הפרויקט.
- **מפתח סודי** (`sb_secret_…` או service_role) לעולם לא נכנס לאפליקציה, למאגר או לצ'אט. הבנייה נכשלת אם מכניסים מפתח סודי.

## 4. התחברות: אורח, Google, Apple, וקוד בדוא״ל

**הכיוון:**
- אורח כברירת מחדל.
- Google ו-Apple כדרך הכניסה העיקרית לחשבון.
- **הקוד בדוא״ל:** זה המימוש הקיים, והוא נשאר כגיבוי. זו לא החלטה חדשה שאושרה.

**מה כבר מוכן בקוד** (בבניית פיתוח ו-staging בלבד):
- **ה-flow:** OAuth עם PKCE בדפדפן של המערכת, לא בתצוגת דפדפן בתוך האפליקציה.
- **החזרה לאפליקציה:** בכתובת `mitzvotplus://auth/callback`.
  - הסכמה `mitzvotplus` כבר רשומה ב-Android וב-iOS.
- **קוד שהאפליקציה לא ביקשה:**
  - קישור מזויף, או קוד של טלפון אחר, לא מתקבל.
  - זה נבדק מול התחליף המקומי.
- **הכפתורים:** "המשך עם Google" ו"המשך עם Apple" מוצגים רק כשהם ב-`VITE_AUTH_PROVIDERS=google,apple`, ורק אחרי שהספקים הוגדרו בפרויקט.

**מה צריך לעשות בלוח הבקרה:**
1. **Authentication → URL Configuration → Redirect URLs:** להוסיף `mitzvotplus://auth/callback`.
2. **Google** (Authentication → Providers → Google):
   - **ב-Google Cloud Console:**
     - ליצור OAuth client מסוג **Web application**.
     - ב-Authorized redirect URI להזין `https://<ref>.supabase.co/auth/v1/callback`.
   - **ב-Supabase:** להעתיק את ה-Client ID וה-Client Secret.
   - **הסוד:** נשאר אצלך ובלוח הבקרה. לא בצ'אט ולא במאגר.
3. **Apple** (Authentication → Providers → Apple):
   - **ב-Apple Developer:**
     - ליצור Services ID ומפתח Sign in with Apple.
     - Return URL: אותה כתובת `…/auth/v1/callback`.
   - **ב-Supabase:** להזין את ה-Services ID, ה-Team ID, ה-Key ID והמפתח.
   - **דרישות:** חשבון Apple Developer בתשלום. וכשמציעים Google ב-iOS, Apple דורשת להציע גם את Apple (סעיף 4.8).
4. **החלטה פתוחה:** כניסה עם ה-SDK הטבעי, כלומר Sign in with Apple ב-iOS ו-Credential Manager ב-Android, במקום הדפדפן.
   - **מה זה נותן:** חוויה טובה יותר.
   - **מה זה דורש:** תוסף נוסף ובדיקה על מכשיר.
   - **ההמלצה:** להתחיל עם ה-flow הקיים ולהחליט אחרי בדיקה בטלפון.

**מה ייבדק על מכשיר**, אחרי שהספקים יוגדרו:
- ביטול הכניסה אצל הספק;
- התחלה קרה מקישור החזרה;
- כניסה כשהאפליקציה פתוחה;
- התנתקות;
- מעבר בין חשבונות.

## 5. גישה, כדי שאריץ את הקבלה בעצמי

אני לא מבקש סודות בצ'אט. יש שלוש רמות:

| רמה | מה צריך | מה זה מאפשר |
|---|---|---|
| קריאה | כתובת ומפתח ציבורי, כמשתני סביבה (`STAGING_SUPABASE_URL`, `STAGING_PUBLISHABLE_KEY`) | בדיקת המצב, סעיף 1 |
| החלת מיגרציות | אתה מריץ `supabase db push`, או טוקן גישה אישי (Personal Access Token) שתוסיף כסוד של הסביבה, לא בצ'אט | סעיף 2 |
| קבלה עם חשבונות | שני חשבונות בדיקה סינתטיים, למשל `tester1@<הדומיין-שלך>`, והסיסמאות שלהם כסודות של הסביבה | שני טלפונים, מחיקת גיבוי וחידושו, יעדים, מחיקת חשבון |

**שתי מגבלות:**
- **הרשת:** הסביבה הזו מגיעה רק לכתובות מותרות. כדי להגיע ל-`<ref>.supabase.co` צריך להוסיף אותה לרשימה, וזה דורש את אישורך.
- **הנתונים:** נתונים סינתטיים בלבד. בלי משתמשים אמיתיים, עד שתאשר מדיניות פרטיות.
